# Blueprint: Duplex P1 交互层（标注 + AI 操作可视化）

## 1. Implied or referenced brief

> 无正式 brief。以下为压缩摘要替代（skill 允许的 Implied brief 形式，需你签收）。

- **Goal:** 让人和 AI 在同一浏览器里「指哪说哪」——人用框/圈/点选标注页面并提问，纯文本 AI 靠代码层锚定的结构化描述理解；AI 的每次操作页面上可见、可被打断。
- **Primary user:** 你自己（开发者/研究者），每天长时间使用，桌面单屏 ~1440×920，深色环境。
- **Primary action:** **在页面上画框 + 就地提问**（人→AI 的核心动作）。
- **Secondary action:** 观察 AI 操作并在必要时按 Esc 接管（AI→人的核心动作）。

## 2. Visual direction

### 2.1 Reference products

- **Primary reference: Arc 浏览器** —— 具体借鉴三点：① 浮动胶囊式工具/提示（不占用固定布局空间）；② 大圆角 + 柔和阴影 + 半透明浮层语言；③ 滑入/淡出的状态过渡（模式切换有"流动性"，不突兀）。
- **Anti-references: Chrome DevTools** —— 属性面板式的工程密度感，工具常驻平铺，不符合"中等密度 + 浮动层"决策（其信息呈现方式可参考，但形态不学）。**传统模态对话框** —— 任何打断流程的 modal 都不采用，所有交互就地完成。

### 2.2 Concrete visual properties

| Property            | Decision                            | Rationale                                 |
| ------------------- | ----------------------------------- | ----------------------------------------- |
| Information density | medium                              | 已由用户显式确认；与现有 UI 一致                        |
| Layout paradigm     | canvas + floating overlays          | 页面是画布；工具、提问、状态全部以浮动层附着其上，永不长期挤占布局         |
| Type                | sans（系统字体栈，延续现状）                    | 浏览器 UI 不需要展示型字体；不引入字体资源                   |
| Color treatment     | accent-on-dark（延续现有深色底 + 单一蓝强调）     | 与现有壳一致；AI 操作状态引入琥珀色（进行中）、红（错误）两个语义色       |
| Surface treatment   | soft-shadow floating（浮层柔和阴影 + 轻半透明） | Arc 式：浮层与页面内容有"悬浮关系"，阴影即层级                |
| Corner radius       | rounded（浮层大圆角，胶囊部件 pill）            | Arc 语言；与现有 8px 圆角体系兼容（浮层 12-16px、胶囊 pill） |
| Mood                | 沉稳的流畅感（calm, flowing）               | 工具状态切换频繁，视觉必须"安静"——动效负责表达状态，颜色不喧哗         |

## 3. Information hierarchy

按"占据屏幕时的优先级"排序（元素天生分时出现，非同时存在）：

| Rank | Element                 | Why it ranks here                |
| ---- | ----------------------- | -------------------------------- |
| 1    | 网页内容本身                  | 一切 UI 服务于它；任何浮层不得长期遮挡内容          |
| 2    | 标注框（可连续画多个；每框左上角带撤销 ×）   | 人意图的直接表达，绘制时刻最高优先，AI 状态条需为其让位；撤销入口必须随手可达 |
| 3    | 就地提问卡片                  | 提问时刻的任务焦点，紧随标注框出现                |
| 4    | AI 状态条（"正在操作 X，Esc 接管"） | AI 操作时的安全锚点——可见即可控；必须半透明薄条、不打断阅读 |
| 5    | AI 光标 + 目标高亮            | AI 动作的视觉指向；动画表达"正在做什么"           |
| 6    | 标注工具胶囊（框/圈/箭头/点选/退出）    | 模式内常驻；由模式状态激活，模式外完全消失            |
| 7    | 右侧面板：标注卡片与对话流           | 历史与上下文查阅；标注卡片是标注的"回执"            |
| 8    | 右侧面板输入框                 | 已有能力，继续保持底部常驻                    |

**⚠ Flagged for review:** 原设想中独立的"标注模式指示条"已删除——其职责并入工具胶囊（胶囊本身即模式指示）。确保没有第 9 项元素需要出现在屏幕上；若发现，应推入面板而非页面浮层。

## 4. Wireframe — primary device

Drawn for: **desktop @ ~1440×920（Windows，Electron 窗口）**

### 状态 A：日常浏览（默认态，P1 不新增常驻元素）

```
+--------------------------------------------------------------------------+
| (tab pill) (tab pill)  [+]                            桌面宽度：1440    |
+--------------------------------------------------------------------------+
|  ← → ⟳   ( 地址胶囊                          )      [✎ 标注]            |
+-----------------------------------------------------+--------------------+
|                                                     |  AI 面板（400px）   |
|                                                     |  ┌──────────────┐  |
|                    网页内容                           |  │ 对话流        │  |
|              （人正常浏览 / AI 操作）                   |  └──────────────┘  |
|                                                     |                    |
|                                                     |  [输入框]  [发送]   |
+-----------------------------------------------------+--------------------+
```

### 状态 B：标注模式（人画框提问）

```
+--------------------------------------------------------------------------+
| (tab pill) (tab pill)  [+]                                               |

|    └───────────────────────────┘                    |                    |

|           ┌───────────────────────────────────┐     |                    |
```

### 状态 C：AI 操作中（操作可视化）

```
+--------------------------------------------------------------------------+
| (tab pill) (tab pill)  [+]                                               |
+--------------------------------------------------------------------------+
|  ← → ⟳   ( 地址胶囊                          )      [✎ 标注]              |
+-----------------------------------------------------+--------------------+
|   ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓  ← AI 高亮当前目标元素        |  AI 面板            |
|                              （描边 + 轻微填充）       |                    |
|                  ◉ ← AI 光标（发光圆点 + 点击涟漪）    |  · AI: 正在点击…    |
|                                                     |                    |
|                                                     |                    |
|          ┌─────────────────────────────────────┐    |                    |
|          │ ◉ AI 正在操作：点击「登录」    Esc 接管 │ ← 状态条（底部居中） |                    |
|          └─────────────────────────────────────┘    |                    |
+-----------------------------------------------------+--------------------+
```

### Reading order

1. **状态 B：** 人的视线先落在**刚画出的框**（高对比白色/蓝色描边 + 微光），再自然下移落到**就地提问卡片**（唯一发光输入区），最后余光扫到**底部工具胶囊**（状态提示）。
2. **状态 C：** 视线先被**AI 光标 + 目标高亮**捕获（页面上的动点），再落到底部**状态条**确认"它要做什么"，打扰结束即消失。
3. **默认态：** 页面第一，面板第二，壳部件（标签/地址）第三。

### Whitespace decisions

- **Generous whitespace around:** 就地提问卡片——它必须从页面视觉中"浮出来"，四周阴影留白 ≥ 16px，与框保持 ≤ 240px 视线距离。
- **Tighter spacing between:** 工具胶囊内部按钮——它们是同等权重的模式选择器，间距压缩成一组（4-6px），整体再与屏幕边缘拉开 ≥ 32px 呼吸距离。
- **状态条极薄（估 ~36px 高）且半透明**——它的存在感必须低于网页内容（rank 1 的约束）。

## 5. Responsive behavior

产品为桌面应用，"响应式" = **窗口宽度适配**（最小 960×600）。

| Breakpoint           | Behavior                                                                                                                           |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Wide (≥1200px)       | 布局如线框：面板 400px 常驻；工具胶囊完整文字标签。                                                                                                      |
| Medium (1050–1199px) | 面板允许拖动收窄至 320px；工具胶囊保持。                                                                                                            |
| Narrow (<1050px)     | 面板 **collapse** 为右侧 28px 竖条（点击后以浮层 **swap** 方式展开覆盖内容区，不再挤压页面）；就地提问卡片 **resize** 至视口宽 −48px 以内；工具胶囊 **hide** 文字标签，只留图标（hover 显示提示）。 |
| Min window (960×600) | 全部功能可用；AI 状态条与工具胶囊 **stack** 为上下两层（各占一行，底部居中）。                                                                                     |

**Critical reflow rules:**

- 所有浮层（提问卡片、工具胶囊、状态条）**永不遮挡正在交互的目标**：画框时工具胶囊自动 **move** 至底部；提问卡片默认在框下方 16px，若下方空间不足则 **swap** 到框上方。
- AI 状态条在任何断点下都固定在底部中央——它是人的"接管刹车"，位置必须稳定可预期。
- 任一浮层出现时，按下 `Esc` 优先关闭浮层（而非退出模式）；再按一次才退出模式——退出顺序与视觉层级一致。
- 撤销（框左上角 `×`）只删除该框，不影响模式与其它框；删除后不弹确认（可重画）。

## 6. What is NOT decided yet

留待 `ui-component-spec` 或实现阶段（本蓝图刻意不指定）：

- 具体组件状态（hover / focus / active / disabled / 空状态）
- 精确颜色值、字号、间距、阴影参数（沿用现有 token，微调在实现时定）
- 动画时长与缓动曲线（方向已定：滑入/淡出、~200ms 量级，实现时调参）
- 标注模式快捷键的具体键位
- 图标的具体选择（已有 lucide-react 依赖，从其中选）
- AI 高亮/光标在跨 iframe 场景的降级表现

## 7. Open questions

1. 「画圈」「箭头」的手势：工具胶囊点选切换（默认方案，简单可预期）还是"框+圈"混合手势识别？**先做前者**。
2. AI 状态条上的「Esc 接管」：是纯提示文字还是可点击按钮？（两者：文字提示 + 点击等效 Esc）
3. 标注提交后，就地提问卡片是**淡出消失**（标注卡片在面板出现）还是留在原位变成"已提交"态？（淡出——面板是回执的家）
4. 【已决·用户确认】**做连续标注模式**：画完一个框不退出模式，可继续画下一个；每个框左上角有 `×` 可随时撤销（含未提交与已提交的框）；Esc 退出模式。

## 8. Assumptions made

- ⚠ 延续现有深色主题与色板（#0f1216 / #1a212a / 强调蓝 #4da3ff），只新增琥珀色（AI 进行中）与红（错误）两个语义色——如需换色板请提出。
- ⚠ 桌面应用无移动端；"响应式"仅指窗口宽度（第 5 节）。
- ⚠ 浮层实现基于注入页面的 Shadow DOM overlay（既有技术方案），因此不受页面 CSS 影响，但 z-index 需极高层。
- ⚠ 本蓝图只覆盖 P1 交互层（标注 + 操作可视化 + 面板标注卡片）；壳部件（标签/地址栏）的 Arc 化视觉迭代列为**后续**，不在本期实现范围。
- ⚠ 沿用 "calm, flowing" 情绪方向——动效表达状态，颜色不喧哗。
- ⚠ 连续标注下：提交后的框以弱化样式（细虚线、低透明度）保留在页面，`×` 仍可撤销；退出标注模式时视觉隐藏（标注数据仍在面板），重新进入时恢复显示。
