# 设计画布：艺术家式网站生成

这一轮把 Duplex 从"AI 能操作浏览器"推进到"AI 和设计师一起造页面"。设计原则只有一句：

> **任何时候屏幕上的东西都必须是"一个可解释的界面状态"，而不是"一段还没写完的代码的样子"。**

## 为什么是 Duplex

| 别人的 AI 建站器 | Duplex |
| --- | --- |
| 预览是 iframe，产物是黑箱 | 预览是**我们自己的页面**：节点 id 写进 `data-did`，地址精确 |
| AI 改完你才能看 | patch 流**事务性**应用：每个中间态都合法、可解释 |
| 你只能用 prompt 表达 | 可以直接拖、点定位器、输数值——**设计动作就是输入** |
| 改坏了只能重生成 | 每轮进 git，撤销到元素级 |

## 四层结构

```
文档模型 (src/shared/design/model.ts)
   ↓ patch（唯一修改入口）
设计服务 (src/main/design/)        画布页面 (src/canvas/)
   · 文档持久化 + 原子写              · 渲染节点树（data-did）
   · 轮次 git 提交 + 导出             · 选择 / 拖拽 / 吸附 / 检视器
   · 撤销重做（反向 patch）           · 定位器 / 放大镜 / 测量尺
   · 约束（用户意图）                 · 变体对比 / 断点预览
   ↓ IPC                              ↑ 用户动作（全部变成约束或 patch）
主进程 (index.ts)
   · design_* 工具（agent 走这里）
   · canvas 专用 preload（消息白名单）
```

## 关键设计决定

**1. 文档是真相（新项目），代码是产物**
生成的站点由文档确定性渲染，导出时再序列化。这样元素地址、约束、撤销、跨断点对齐才有共同依据。接别人的已有项目时反向：代码是真相，文档是运行时投影。

**2. `data-did` 是正当的**
在**我们自己的产物**上写稳定节点 id 不违反"第三方页面零指纹"的原则——它属于站点源码，不是注入到别人页面里的探测标记。

**3. patch 是唯一修改入口**
agent 与用户都走 `applyPatch`。撤销 = 反向 patch，不依赖 git；git 只承担"轮次里程碑"。锁定区的 agent patch 会被拒绝并给出原因，用户操作可以覆盖。

**4. 定位表达意图，agent 负责响应式正确性**
用户在设计帧（默认 1440）里把元素锚点对齐到目标点，落库成约束 `{anchor, point, frameWidth}`；agent 决定用 absolute / grid / transform 实现，并回报实际做法。坐标永远带着"帧"一起存，否则跨断点无意义。

**5. 光标是遥测，不是表演**
多 agent 光标状态由执行方给出（思考/移动/等待写权/被人接管/失败），阻塞时光标必须停住，不允许假装在干活。

## 功能清单（本轮）

- 九点锚点 + 8px 网格吸附的**定位器**（幽灵预览 + 参考线，确认后才应用）
- **像素取样放大镜**（克隆缩放 + 坐标/尺寸/颜色读数）与整体视图缩放
- **测量尺**（两点距离、水平/垂直分量、拖拽对齐线）
- **直接拖拽 + 数值检视器**（方向键 1px 微调，落成 patch）
- **变体对比**（同一区块 2–3 个方案并排选一）
- **多断点预览**（桌面 1440 / 平板 834 / 手机 390 + 宽度滑杆）
- **git 轮次**：每轮一个提交，历史可查，可安全 revert；**导出 zip**
- **设计工具**：`design_open` / `design_read` / `design_patch` / `design_commit` / `design_export`
- **多 agent 光标**：单/多 agent 共用同一套动画，状态真实

## 怎么用（验收）

1. `npm run build`（画布是独立构建产物，输出 `out/canvas/`）
2. 启动应用 → 工具栏点 **✦ 设计** → 打开画布标签
3. 让内置 agent："在画布上做一个落地页：首屏左文右图，下面是三张特性卡，用现有 tokens"
4. 观察：agent 的 patch 逐步出现（每个中间态都完整），刚改的区域有 diff 高亮
5. 拖动任意卡片 → 幽灵 + 吸附线 → 松手后检视器出现精确坐标
6. 点「定位」→ 点目标位置 → 确认后元素按锚点对齐
7. 按 `M` 放大镜、`R` 测量两点距离、`Z` 切换整体缩放
8. 点「变体」让 agent 给同一区块三个方案 → 并排选一个
9. 切到手机 390 → 同一元素跨断点高亮 → 确认没有断裂
10. 点「提交这一轮」→ 填一句摘要 → 历史里出现新提交；点「导出」得到 zip

## 已知边界（本轮）

1. 画布只渲染我们自己的 12 个原语（box/stack/grid/text/heading/button/input/image/spacer），不解析任意 HTML
2. 文档是真相的模式下，导出是"从文档生成静态页面"，不是工程级脚手架
3. 撤销栈只在内存里（重启后靠 git 轮次回退）
4. 多视口是同一文档的不同宽度渲染，不是真正的多端联调
5. agent 光标只在页面上可见，画布内的光标位置由 patch 触发的位置近似

## 与多 agent 的关系

这一轮复用之前的地基：按 agent 隔离的授权（生成站点不需要站点授权，但 agent 调用 `run_command`/`write_file` 仍受约束）、仲裁（两个 agent 同时改不同区块时同一目标串行）、以及归属（patch 记录 actor，时间线可回答"谁改的"）。

### 本轮发现的限制（下一轮优先）

1. **绝对定位与流式布局会打架**：把网格里的卡片拖成 `absolute` 后，网格留下空位、手机布局错位。这是"自由摆放 vs 响应式"的固有矛盾——下一步要给用户两个明确的移动模式：**自由摆放（absolute）** 与 **槽位交换（grid/flex order）**，并在检视器里显示当前模式。
2. **变体缩略图是简化渲染**：只画文本/背景/尺寸，不渲染图片与嵌套样式；选择后应用完整节点。
3. **iframe / 滚动容器**：定位器与放大镜只覆盖顶层文档，嵌套滚动容器内测量线会漂（overlay 报告已列）。
4. **画布只支持我们自己的 12 个原语**，不解析任意 HTML；导出是从文档生成静态页面，不是工程脚手架。
5. **撤销栈在内存**，重启后只能靠 git 轮次回退；约束/变体不进入撤销栈（只覆盖 patch）。

## 给下一轮的明确任务

1. 移动模式二选一（自由摆放 / 槽位交换），并让 agent 知道用户用了哪种。
2. 变体缩略图改为真实渲染（复用 `renderDocument` 到小尺寸容器）。
3. 画布输出"可交付"导出：生成 `index.html` + `styles.css`（token → CSS 变量），不再只导出 design.json + zip。
4. 多 agent 光标接到画布：agent patch 时按目标节点位置驱动光标（现在光标层只在普通页面可用）。
