# Duplex 0.2.5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an isolated Duplex 0.2.5 desktop demo with practical browser features, working downloads, and explicit OpenCode opt-in.

**Architecture:** Retain Electron WebContentsView tabs and the persistent browser session. Add a bounded browser-data store and a download manager in main, expose them through typed IPC, then compose focused browser panels in the renderer. Keep OpenCode integration additions separate from the normal mirror plugin; provide an isolated preview data directory so the original installation/profile stays untouched.

**Tech Stack:** Electron 44, React 19, TypeScript 7, electron-vite, OpenCode Desktop slash commands/agents.

**Spec:** `docs/superpowers/specs/2026-10-05-duplex-025-design.md`

## Global Constraints

- All source changes stay on `codex/v0.2.5` in `CoBrowse-0.2.5`; leave the original checkout and installed 0.2.1 untouched.
- Keep credentials out of browser-data.json, repository files, logs, and screenshots.
- Browser records are local only; cap history at 5,000 and downloads at 500.
- Ordinary OpenCode agents deny Duplex MCP tools; explicit commands select the dedicated agent.
- Do not publish, tag, or alter existing release assets.
- Verify with typecheck, production build, and isolated demo launch; do not execute test suites unless requested.

---

## File map

- `src/main/browser-data.ts`: bounded local bookmarks, history, and download metadata persistence.
- `src/main/downloads.ts`: Electron DownloadItem lifecycle, progress, cancellation, open/reveal.
- `src/main/tabs.ts`: main-frame history/favicon/closed-tab state and context action support.
- `src/shared/protocol.ts`: shared browser record and download event types.
- `src/main/index.ts`: initialize isolated paths/store, wire browser IPC and downloads.
- `src/preload/index.ts`, `src/renderer/src/env.d.ts`: typed renderer bridge.
- `src/renderer/src/App.tsx`, `src/renderer/src/components/Toolbar.tsx`, `StartPage.tsx`, new `BrowserPanel.tsx`, `TabBar.tsx`, `styles.css`: browser-first interface and panels.
- `src/renderer/src/components/SidePanel.tsx`: preserve AI panel behavior while making collapsed state the default.
- `src/shared/endpoint.ts`: preview data-directory override.
- `package.json`, `src/main/index.ts`: 0.2.5 metadata/version.
- `.opencode/agents/duplex.md`, `.opencode/commands/duplex.md`, `duplex-task.md`, `duplex-stop.md`, `opencode.example.json`: explicit opt-in command setup and reversible example.
- `scripts/preview-0.2.5.cmd`: launches a demo with a dedicated user-data folder.

## Task 2: Browser-data store and tab metadata

- [ ] Define persisted records and bounded JSON read/write operations in `browser-data.ts`, writing atomically to a separate `browser-data.json`.
- [ ] Record only top-level HTTP(S) commits, retain at most 5,000 newest history entries, and support search, remove, and clear.
- [ ] Add bookmark toggle/list/search.
- [ ] Capture favicon URLs and last-closed-tab URL; expose tab context actions (duplicate, close others, close right, reopen closed) through existing tab action IPC.
- [ ] Add IPC handlers and typed preload methods; keep filesystem operations in main only.

## Task 3: Download lifecycle

- [ ] Attach `will-download` to `session.fromPartition('persist:cobrowse')` before tabs are created; set save path to the OS Downloads directory.
- [ ] Stream progress/status snapshots to renderer and persist completed/interrupted metadata, trimming old records to 500.
- [ ] Support cancellation, open, reveal, and clearing metadata without deleting files.
- [ ] Restore in-progress rows as interrupted after restart.
